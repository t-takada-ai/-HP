# X運用自動化基盤

X(Twitter)投稿を「データ分析 → ネタ帳 → 生成 → 予約 → 台帳更新」のサイクルで半自動運用するための Claude Code 基盤。

参考にした運用システム(星野式)の設計思想:

1. **ネタはIDで一意管理** — 思いつきで作らず、ネタ帳からIDで選ぶ
2. **使用済み台帳** — 使ったネタは台帳に記録し、二度と使わない(再放送禁止)
3. **機械的な重複チェック** — 採用前に過去投稿索引をgrepして被りを検出
4. **1投稿=1サイクル** — 選定→生成→入稿→台帳更新→ログ追記までを1セットとして完了扱い
5. **データドリブンな改訂** — ネタ帳は分析レポートから定期的に再生成しバージョンアップ(v1→v2→…)

## ディレクトリ構造

```
├── CLAUDE.md                  # 全セッション共通の運用ルール(鉄則)
├── materials/                 # データ層(分析・索引・一次情報)
│   ├── master_databank.md     # 自分の一次情報データバンク(体験・実績・エピソード)
│   ├── past_posts_index.md    # 全投稿タイプ横断の索引(重複チェック照合元)
│   └── x_analysis_report.md   # 投稿データ分析レポート(ネタ帳の生成元)
├── .claude/skills/            # スキル層(投稿タイプ別の手順書。Claude Codeが自動発見)
│   ├── x-thread-post-writing/ # ツリー型投稿(ネタ帳.md + 送信用テンプレート + 投稿ログ)
│   ├── x-story-post-writing/  # ストーリー型投稿(idea_bank.md + 投稿ログ)
│   ├── persona-voice-rules/   # 人格・文体ルール(全投稿タイプ共通)
│   └── hook-words/            # フック(冒頭1行)の型カタログ
└── projects/
    └── typefully_post/        # 完成原稿の保管先(入稿ファイル)
```

※ 参考元はリポジトリ直下に `skills/` を置いていますが、ここでは Claude Code が自動発見する
`.claude/skills/` に配置しています。「ツリー投稿を作って」と言うだけでスキルが起動します。

## 立ち上げロードマップ

参考元の「v10・96投稿分析」という完成度は、**この運用ループを回し続けた蓄積の結果**です。
初日から同じ構造で始めれば、蓄積は自動的に貯まります。

- **Phase 0 — 資産の棚卸し**: 過去のX投稿があればエクスポートして `past_posts_index.md` に索引化。
  X実績がなくても、note記事・教材・YouTube等の既存資産から `master_databank.md` を作る。
- **Phase 1 — 分析**: 投稿の反応データ(インプ・いいね・保存)を `x_analysis_report.md` に整理し、
  伸びるクラスタ/伸びないクラスタを特定する。
- **Phase 2 — ネタ帳 v1**: 分析結果からネタをクラスタ分類してID化し、各スキルのネタ帳に登録。
- **Phase 3 — 人格・文体**: `persona-voice-rules` のTODOを埋める(ここが投稿の一貫性を決める)。
- **Phase 4 — 運用開始**: 1日の投稿枠(例: 6:00 / 15:00 / 20:00)を決め、サイクルを回す。
- **Phase 5 — 改訂**: 投稿50件ごと(または月1回)に分析レポートを更新し、ネタ帳をv2, v3…と改訂。

## 使い方(Phase 4 以降の日常運用)

```
「7/25の20:00枠のツリー投稿を作って」
→ x-thread-post-writing スキルが起動し、ネタ帳からID選定→重複チェック→生成→台帳更新まで実行
```

ネタIDを自分で指定してもよい: 「A1で20:00枠を作って」
