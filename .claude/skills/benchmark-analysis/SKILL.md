# ベンチマーク分析スキル

## 目的

他人の伸びたポストを「構造」として抽出し、自分のスキル群に還元する。

**鉄則: 盗むのは構造、コピーしないのは文言。**
語彙・言い回し・固有のエピソードは転用しない。抽出するのは型(構成・フック・リズム・感情曲線)のみ。

## 入力

ユーザーが貼ったポスト(テキスト or スクショ)。複数まとめてでもよい。
わかれば出典(@アカウント)と反応数(インプ・いいね・保存)も受け取る。

## 手順

1. **タイプ判定**: ツリー型(実用・手順)か、ストーリー型(体験談・物語)か判定する。

2. **構造分解**: 以下を必ず全項目分析する。
   - ポストごとの役割(フック/問題提起/本題/転機/まとめ/CTA)
   - フック型: `hook-words/SKILL.md` の既存8型に該当するか。**該当しなければ新型として命名**
   - 文字数リズム(各ポストの長さ配分)
   - 改行リズム(1文ごと改行か、ブロックか、空行の使い方)
   - 感情曲線(読者の感情がどう動く設計か)
   - CTA(最終ポストで読者に何をさせるか)

3. **なぜ伸びたか仮説**: 構造要因を2〜3点に絞って言語化する。

4. **保管庫へ登録**: `materials/reference_posts.md` に Ref番号を採番して所定形式で追記する
   (原文は引用として保存。一覧表にも1行追加)。

5. **スキルへの反映(差分を明示して実行)**:
   - 構成の型 → `x-thread-post-writing/knowledge/success_patterns.md` または
     ストーリー型なら `x-story-post-writing/SKILL.md` の構成節に型として追加
   - 新しいフック型 → `hook-words/SKILL.md` に追加(例文は**自分の題材で書き直す**)
   - ポスト数・字数など形式の発見 → `送信用テンプレート.md` の制約を更新
   - 反映した型には出典を付記する(例「出典: Ref-3」)。後で効果検証できるように

6. **人格フィルタ**: 反映前に `persona-voice-rules` と照合し、キャラに合わない要素は
   理由つきで捨てる(全部を取り込まない。「捨てた部分」も reference_posts.md に記録)。

7. **報告**: Ref番号・抽出した型・反映先ファイルと差分内容・捨てた要素を報告する。

## 完了条件

reference_posts.md への登録と、反映先スキルの更新の両方を終えて完了。
分析だけして「反映しますか?」で止まらない(反映を見送る場合は理由を報告する)。

## 反映後の検証(運用ルール)

反映した型を使った投稿は、投稿ログの「フック型」欄等に Ref番号を残す。
分析レポート更新時に「ベンチマーク由来の型が実際に伸びたか」を検証し、
伸びなければ型を削除または修正する(輸入した型も自分のデータで淘汰する)。
