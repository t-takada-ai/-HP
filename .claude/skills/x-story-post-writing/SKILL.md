# ストーリー型投稿作成スキル

## 前提

- ネタは `knowledge/idea_bank.md` の「ネタ一覧」からIDで選ぶ。使用済み節にあるIDは使わない。
- 主原料は `materials/master_databank.md` の失敗談・体験エピソード。**実話ベースのみ。創作しない**。
- 文体・人格は `persona-voice-rules` に従う(ストーリー型はやや感情の振れ幅を大きくしてよい)。

## ツリー型との違い

| | ツリー型 | ストーリー型 |
|---|---|---|
| 目的 | 保存される実用情報 | 共感・人柄でファン化 |
| 構造 | 手順・リスト | 物語(状況→転落→転機→学び) |
| フック | 数字・ノウハウ | 感情・告白 |

## 手順

1. **枠の確認**(指定がなければユーザーに確認)
2. **ネタ選定**: `idea_bank.md` からID選定。使用済み節を除外。データバンクに実体験の裏付けがあるか確認。
3. **重複チェック**:
   ```bash
   grep -niE "キーワード1|キーワード2" materials/past_posts_index.md .claude/skills/x-story-post-writing/knowledge/past_story_posts.md
   ```
4. **生成**: 4ポスト構成を基本とする。
   - 1ポスト目: 感情フック(結果 or 告白を先に出す。例「○○で全部失いかけた話」)
   - 2ポスト目: 状況と転落(具体的な情景・数字)
   - 3ポスト目: 転機(何に気づき、何を変えたか)
   - 4ポスト目: 学び+読者への橋渡し
5. **セルフレビュー**: 実話から逸脱した誇張がないか。他者を特定できる記述がないか。
6. **入稿ファイル保存**: `projects/typefully_post/story_YYYYMMDD_題材短縮名.txt`
7. **台帳更新(必須・同一ターン内)**:
   - `idea_bank.md`: 使ったIDを「使用済み」節へ移動(使用日・投稿No.を付記)
   - `knowledge/past_story_posts.md` に投稿No.を採番して1行追記
8. **完了報告**: ID・枠・保存先・台帳更新完了を報告。

## 完了条件

台帳2ファイルの更新まで終えて初めて「完了」。
