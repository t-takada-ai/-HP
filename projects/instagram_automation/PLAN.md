# Instagram 投稿編集 自動化 計画書

作成日: 2026-08-14 / v1

## 0. 結論(先に3行)

- **動画・写真の編集、字幕焼き込み、BGM合成、キャプション本文の生成は「完全自動化できる」**。ffmpeg + Whisper系 + 既存のスキル資産で組める。
- **Instagramの音源ライブラリ(トレンド音源)をAPIから付けることは「不可」**。これはMeta側の仕様で、回避策はない。アプリで手作業になる。
- したがって推奨は **「編集は全自動 → 完成物をアプリで投稿(音源はそこで付ける)」の半自動運用**。API自動投稿(Phase 5)は、審査・ホスティング・トークン管理のコストに対して、結局アプリを開く必要が残るため優先度は低い。

---

## 1. 要件ごとの可否

### 要件① 字幕・キャプションの挿入

「字幕」と「キャプション」は別物なので分けて扱う。

| 項目 | 可否 | 手段 / 備考 |
|---|---|---|
| 動画への字幕(テロップ)焼き込み | ✅ 完全自動 | ffmpeg の `subtitles`/`ass` フィルタ。フォント・縁取り・位置をテンプレ固定できる |
| 台本ありの字幕タイミング付け | ✅ 完全自動・誤字ゼロ | stable-ts の**強制アライメント**(`align`)。文言は台本のまま、時間だけ音声から取る |
| 台本なし実写素材の字幕起こし | ⚠️ 半自動 | Whisper で文字起こし → **固有名詞・専門用語は誤変換するので目視校正が必須**。用語辞書で置換すれば大半は潰せる |
| 投稿本文(caption)の自動生成 | ✅ 完全自動 | 既存の `persona-voice-rules` / ネタ帳資産をそのまま流用できる |
| 投稿本文のAPI送信 | ✅ 可(Phase 5) | コンテナ作成時に `caption` を渡す |
| **公開後のキャプション編集** | ❌ API不可 | 更新エンドポイントが存在しない。直すなら削除→再投稿。**校正は入稿前に確定させる運用が必須** |
| Instagram純正の「自動字幕」スタンプ | ❌ API不可 | アプリ内機能。焼き込み字幕で代替する(フォント統一できる分むしろ有利) |
| ストーリーズのスタンプ・リンク・アンケート | ❌ API不可 | 付けるならアプリで手作業 |

### 要件② 音楽の挿入

| 項目 | 可否 | 手段 / 備考 |
|---|---|---|
| ロイヤリティフリーBGMの合成 | ✅ 完全自動 | ffmpeg で `amix`。ナレーションがある場合は `sidechaincompress` で自動ダッキング(喋る所だけBGMを下げる) |
| 音量のノーマライズ | ✅ 完全自動 | `loudnorm` で -14 LUFS 前後に統一。投稿ごとの音量バラつきが消える |
| フェードイン/アウト、頭出し、尺合わせ | ✅ 完全自動 | `afade` / `atrim` |
| **Instagramの音源ライブラリから曲を選んで付ける** | ❌ **不可** | Meta がAPIに公開していない。アプリ内でのみ可能。**回避策なし** |
| リールの音源名(オリジナル音源)の設定 | △ 条件付き | `audio_name` パラメータ。Facebook Login 接続アカウントのみ、かつ**1回しか設定できない** |

**判断が必要な点**: リーチ面ではIG純正のトレンド音源が有利とされる。ここは二択。

- **A案(自動優先)**: BGMを焼き込む。編集完了 = 投稿可能。API自動投稿まで一直線に繋がる。
- **B案(リーチ優先)**: 動画は無音 or 環境音のみで書き出し、アプリで音源を付けて投稿。**投稿だけは必ず手作業になる**。

→ 推奨は **B案をデフォルト、A案(BGM焼き込み)はナレーション動画に限定**。理由は3節。

> ⚠️ 著作権注意: 市販曲を焼き込むとIG側の自動検出でミュート/リーチ制限がかかる。焼き込むのはライセンス取得済み音源(Epidemic Sound、Artlist、YouTube Audio Library 等)に限定する。

### 要件③ 動画・写真の簡易編集

| 項目 | 可否 | 備考 |
|---|---|---|
| アスペクト比変換(9:16 / 4:5 / 1:1) | ✅ 完全自動 | クロップ or 背景ぼかしパディング |
| トリム(頭尻カット)・複数クリップ連結 | ✅ 完全自動 | 秒数指定 or カット表指定 |
| 無音区間の自動カット(ジャンプカット) | ✅ 完全自動 | `silencedetect` で無音検出 → 自動で詰める。**尺短縮に一番効く** |
| 速度変更・フェード・簡易トランジション | ✅ 完全自動 | `setpts` / `xfade` |
| ロゴ・ウォーターマーク・固定テロップ合成 | ✅ 完全自動 | `overlay` / `drawtext` |
| カバー(サムネイル)画像の自動抽出 | ✅ 完全自動 | 指定秒のフレーム書き出し + 文字入れ |
| 色調補正・明るさ調整 | ✅ 完全自動 | `eq` / LUT 適用 |
| IG仕様へのエンコード統一 | ✅ 完全自動 | H.264 / yuv420p / AAC / `+faststart` |
| 写真のテンプレ合成・カルーセル一括生成 | ✅ 完全自動 | Pillow か ImageMagick。図解テンプレの量産に有効 |
| **「いい感じに」切り抜く・尺を詰める判断** | ❌ 非現実的 | 何が"いい感じ"かの定義が要る。**テンプレ化して初めて自動になる** |
| 被写体追従クロップ(横動画→縦動画の自動リフレーム) | ⚠️ 要追加ツール | 顔/人物検出モデルが必要。専用SaaS(OpusClip等)を使う方が早い |
| モーショングラフィックス・凝った演出 | ❌ 実質不可 | 手作業(CapCut/Premiere)の領域 |

## 2. 投稿そのものの自動化(参考: Phase 5 の前提)

編集ではなく「投稿」まで自動化する場合の条件。**やらない判断も含めて把握しておくべき制約**。

| 項目 | 内容 |
|---|---|
| アカウント要件 | プロアカウント(ビジネス/クリエイター)必須。個人アカウントはAPI利用不可 |
| 認証 | ①Instagram Login(Facebookページ不要・新しい方) ②Facebook Login(ページ連携必須・`audio_name` 等が使える) |
| 事前手続き | Metaアプリ作成 + **アプリレビュー + ビジネス認証**(数日〜数週間かかる) |
| **素材の受け渡し** | **ファイルを直接アップロードできない。公開HTTPSのURLが必須** → S3 / Cloudflare R2 等のホスティングが要る |
| 投稿フロー | 2段階(メディアコンテナ作成 → `media_publish`) |
| 対応メディア | 画像 / リール / カルーセル(2〜10枚) / ストーリーズ |
| 投稿上限 | 24時間ローリングで **100件**(公式リファレンスに「50」の古い記載が残っている。運用時は `content_publishing_limit` で実値を確認する) |
| **予約投稿** | **APIに機能なし。自前スケジューラ(cron / GitHub Actions)で指定時刻に発火させる必要がある** |
| トークン | 長期トークンも定期更新が必要(切れると無言で止まる)。監視が要る |

※ メディア仕様(尺・ファイルサイズ上限等)は変動するため、実装時に公式docsで最新値を確認すること。本計画書の数値は二次情報ベース。

## 3. 推奨アーキテクチャ

> **「編集は全自動、投稿は半自動」から始める。**

理由:

1. **どのみちアプリを開く必要が残る**。IG音源もストーリーズのスタンプもAPIでは付けられない以上、API自動投稿を作っても「音源なしのリールだけ完全自動、それ以外は手作業」という中途半端な二重運用になる。
2. **コスト対効果が逆転している**。1日2〜3投稿なら手動投稿は1件1分以下。対してPhase 5は、アプリ審査 + 素材ホスティング + トークン更新監視という**恒常的な保守コスト**を背負う。
3. **時間を食っているのは投稿操作ではなく編集**。字幕付け・尺詰め・音量調整・書き出しが1本あたり30分〜1時間。ここを自動化するだけで効果の9割が取れる。

```
素材(動画/写真) ─┐
ネタ帳ID ─────────┤
                  ↓
        [Phase 1] 編集エンジン(ffmpeg)
        トリム / 無音カット / 9:16化 / 色調 / ロゴ
                  ↓
        [Phase 2] 字幕エンジン(stable-ts + ASS)
        文字起こし or 強制アライメント → 焼き込み
                  ↓
        [Phase 3] BGM合成 + 音量ノーマライズ  ※B案なら無音書き出し
                  ↓
        [Phase 4] 入稿パッケージ生成
        final.mp4 / cover.jpg / caption.txt / hashtags.txt
                  ↓
            手動投稿(アプリで音源を付けて投稿)
                  ↓
        [Phase 5] API自動投稿 ← 運用が固まってから判断
```

### ディレクトリ設計案

```
projects/instagram_automation/
├── PLAN.md                    # 本ファイル
├── scripts/
│   ├── edit_video.py          # トリム・無音カット・9:16化・エンコード
│   ├── burn_captions.py       # 字幕生成 → ASS → 焼き込み
│   ├── mix_audio.py           # BGM合成・ダッキング・loudnorm
│   ├── make_carousel.py       # 写真テンプレ合成(カルーセル)
│   └── build_package.py       # 入稿一式の書き出し
├── templates/
│   ├── caption.ass            # 字幕スタイル(フォント・色・位置)
│   └── carousel/*.png         # 図解テンプレ
├── bgm/                       # ライセンス取得済み音源のみ
└── work/<post-id>/
    ├── source/                # 元素材
    ├── recipe.json            # この投稿の編集指示(単一の正解情報源)
    └── out/                   # final.mp4 / cover.jpg / caption.txt
```

`recipe.json` を単一の正解情報源にする(既存 `ai-video-pipeline` スキルの `script.json` と同じ思想)。カット位置・字幕テキスト・BGM・キャプション本文を1ファイルに集約し、各スクリプトはそこだけを読む。**やり直しが効く**のが重要。

### 既存資産の再利用

このリポジトリのX運用基盤の思想は、そのままInstagramにも効く:

- `.claude/skills/instagram-post-editing/` としてスキル化 → 「この動画をリールにして」で起動
- **ネタID管理・使用済み台帳・重複チェック(CLAUDE.md の鉄則)をInstagramにも適用**する。`instagram_idea_bank.md` を新設し、台帳を分ける
- `persona-voice-rules` はキャプション本文にそのまま流用(文体の一貫性が保てる)
- 字幕・書き出しの実装は `ai-video-pipeline` スキルの Step 5 / Step 6 がほぼそのまま使える

## 4. 実装フェーズ

| Phase | 内容 | 成果 | 目安 |
|---|---|---|---|
| **0. 環境整備** | ffmpeg / stable-ts の導入、日本語フォント(Noto Sans JP)配置、ディレクトリ規約の確定 | 動く土台 | 半日 |
| **1. 編集エンジン** | `edit_video.py`(トリム・無音カット・9:16化・エンコード統一) | **ここが本体。効果が一番大きい** | 1〜2日 |
| **2. 字幕エンジン** | `burn_captions.py` + `caption.ass` スタイル確定 | テロップ入れ作業が消える | 1日 |
| **3. 音声処理** | `mix_audio.py`(BGM・ダッキング・loudnorm) | 音量のバラつきが消える | 半日 |
| **4. 入稿パッケージ + スキル化** | `build_package.py`、Instagramスキル + ネタ帳・台帳の新設 | 「素材を渡す→投稿直前まで完成」 | 1〜2日 |
| **5. API自動投稿(任意)** | Metaアプリ審査、素材ホスティング、スケジューラ、トークン監視 | 完全自動(ただし音源なしリールのみ) | 数日〜数週間(審査待ち含む) |

Phase 1〜4 を先に回して、手作業の残量を実測してから Phase 5 の要否を判断するのが妥当。

## 5. 事前に決める必要があること

1. **音源の方針** — A案(BGM焼き込みで完全自動)か B案(IG音源のためアプリ投稿)か。ここで Phase 3 と Phase 5 の設計が変わる。
2. **主な投稿フォーマット** — リール中心か、図解カルーセル中心か。前者なら動画編集、後者なら画像テンプレ合成に工数を寄せる。
3. **字幕スタイル** — フォント・色・縁取り・位置(縦型はUIに隠れる上下を避ける)。参考にしたいアカウントがあれば提示してもらう。
4. **元素材の入手経路** — 自分で撮影 / AI生成(既存 `ai-video-pipeline` から接続可)/ ストック素材。
5. **投稿頻度** — 1日1本なら手動投稿で十分。1日5本以上なら Phase 5 の価値が出てくる。

## 6. 既知の落とし穴

- **日本語フォントがないと字幕が豆腐(□□□)になる** — ffmpeg の subtitles フィルタはシステムフォント参照。Noto Sans JP 等を明示的に入れる。
- **ffmpeg のフィルタ構文はパスの特殊文字(コロン・カンマ)で壊れる** — 字幕ファイルは単純な名前でカレントに置いてから実行する。
- **公開後のキャプション修正はAPIでは不可** — 誤字は削除→再投稿になり、いいね等が消える。**入稿前の校正を運用に組み込む**。
- **市販曲の焼き込みは自動ミュート/リーチ制限のリスク** — 音源はライセンス管理を必ず行う。
- **APIトークン切れは無言で止まる** — Phase 5 に進むなら失敗通知の仕組みまでセットで作る。
- **Whisper の文字起こしは固有名詞に弱い** — 用語辞書での後処理と目視校正を工程に入れる。
